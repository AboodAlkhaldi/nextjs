## CKA Exam Reference — Complete Study & Scenario Guide

Based on official **2025 curriculum** (effective February 18, 2025).  
**Kubernetes version**: v1.32+  
**Exam format**: 2 hours, performance-based, ~15–20 tasks, passing score **66%**.  
You work across **6 different clusters** — **always check context before each task**.  
Only allowed resource during the exam: [`kubernetes.io/docs`](https://kubernetes.io/docs/).

### Domain weights

- **Troubleshooting**: 30%
- **Cluster architecture, installation & configuration**: 25%
- **Services and networking**: 20%
- **Workloads and scheduling**: 15%
- **Storage**: 10%

### High‑value exam tips

- **Aliases**: Set useful `kubectl` aliases immediately when the exam starts (`k`, `kn`, etc.).
- **Context**: Always switch to the **given context** before each task.
- **Dry‑run YAML**: Use `--dry-run=client -o yaml` to generate YAML quickly.
- **Docs search**: Prefer `kubectl explain` and the search box at `kubernetes.io/docs`.
- **Timeboxing**: Skip hard questions and come back later.

# ===========================================================================
# 1A: RBAC — Role-Based Access Control
# ===========================================================================

# --- Core RBAC objects ---
# Role        — namespace-scoped permissions
# ClusterRole — cluster-scoped permissions (or reusable across namespaces)
# RoleBinding        — bind Role or ClusterRole to subject (in a namespace)
# ClusterRoleBinding — bind ClusterRole to subject cluster-wide

# --- Create Role (namespace-scoped) ---
kubectl create role pod-reader \
  --verb=get,list,watch \
  --resource=pods \
  --namespace=my-ns

# Role with specific resource names
kubectl create role pod-reader \
  --verb=get \
  --resource=pods \
  --resource-name=my-pod \
  --namespace=my-ns

# Role for multiple resources
kubectl create role app-role \
  --verb=get,list,watch,create,update,patch,delete \
  --resource=pods,deployments,services \
  --namespace=my-ns

# --- Create ClusterRole ---
kubectl create clusterrole node-reader \
  --verb=get,list,watch \
  --resource=nodes

kubectl create clusterrole secret-admin \
  --verb='*' \
  --resource=secrets

# --- Create RoleBinding ---
# Bind Role to a User
kubectl create rolebinding pod-reader-binding \
  --role=pod-reader \
  --user=alice \
  --namespace=my-ns

# Bind Role to a ServiceAccount
kubectl create rolebinding pod-reader-binding \
  --role=pod-reader \
  --serviceaccount=my-ns:my-sa \
  --namespace=my-ns

# Bind ClusterRole in a specific namespace (gives namespace-scoped access)
kubectl create rolebinding admin-binding \
  --clusterrole=admin \
  --user=alice \
  --namespace=my-ns

# --- Create ClusterRoleBinding ---
kubectl create clusterrolebinding node-reader-binding \
  --clusterrole=node-reader \
  --user=alice

kubectl create clusterrolebinding sa-cluster-admin \
  --clusterrole=cluster-admin \
  --serviceaccount=kube-system:my-sa

# --- Verify permissions ---
kubectl auth can-i get pods --as=alice
kubectl auth can-i get pods --as=alice --namespace=my-ns
kubectl auth can-i get pods --as=system:serviceaccount:my-ns:my-sa
kubectl auth can-i '*' '*'                          # is admin?
kubectl auth can-i get pods --as=alice --all-namespaces

# EXAM SCENARIO 1: Create SA with specific permissions
# "Create a ServiceAccount named 'deployer' in namespace 'apps'.
#  Create a Role that allows get, list, watch on deployments.
#  Bind the Role to the ServiceAccount."
kubectl create namespace apps
kubectl create serviceaccount deployer -n apps
kubectl create role deployment-viewer \
  --verb=get,list,watch \
  --resource=deployments \
  -n apps
kubectl create rolebinding deployer-binding \
  --role=deployment-viewer \
  --serviceaccount=apps:deployer \
  -n apps
# Verify:
kubectl auth can-i get deployments \
  --as=system:serviceaccount:apps:deployer -n apps    # should be: yes

# EXAM SCENARIO 2: ClusterRole for node info
# "Create a ClusterRole 'node-viewer' that allows get,list on nodes.
#  Bind it to user 'bob' cluster-wide."
kubectl create clusterrole node-viewer --verb=get,list --resource=nodes
kubectl create clusterrolebinding bob-node-viewer \
  --clusterrole=node-viewer --user=bob
kubectl auth can-i list nodes --as=bob               # yes
kubectl auth can-i list pods --as=bob                # no

# --- RBAC YAML examples ---
cat << 'EOF'
# Role YAML
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: pod-manager
  namespace: my-ns
rules:
- apiGroups: [""]           # "" = core API group (pods, services, configmaps)
  resources: ["pods"]
  verbs: ["get", "list", "watch", "create", "delete"]
- apiGroups: ["apps"]       # apps group (deployments, replicasets)
  resources: ["deployments"]
  verbs: ["get", "list", "watch"]
---
# RoleBinding YAML
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: pod-manager-binding
  namespace: my-ns
subjects:
- kind: User
  name: alice
  apiGroup: rbac.authorization.k8s.io
- kind: ServiceAccount
  name: my-sa
  namespace: my-ns
roleRef:
  kind: Role                # Role or ClusterRole
  name: pod-manager
  apiGroup: rbac.authorization.k8s.io
EOF

# 1B: KUBEADM — Cluster Bootstrap & Upgrade

# --- Initialize a cluster ---
kubeadm init \
  --pod-network-cidr=10.244.0.0/16 \          # for Flannel CNI
  --apiserver-advertise-address=<master-ip> \
  --control-plane-endpoint=<lb-ip>:6443        # for HA setup

# Set up kubeconfig after init (as regular user)
mkdir -p $HOME/.kube
sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config

# --- Join a worker node ---
kubeadm token create --print-join-command      # get join command on master
# Run the output on worker node (as root):
# kubeadm join <master-ip>:6443 --token <token> --discovery-token-ca-cert-hash sha256:<hash>

# --- Join a control plane node (HA) ---
kubeadm init phase upload-certs --upload-certs # get certificate key
# Run on new control plane node:
# kubeadm join <lb>:6443 --token <token> --discovery-token-ca-cert-hash sha256:<hash> --control-plane --certificate-key <key>

# --- CLUSTER UPGRADE (most tested kubeadm topic!) ---
# Must upgrade one minor version at a time (1.29 -> 1.30 -> 1.31)
# Always upgrade control plane first, then workers

# Step 1: Upgrade kubeadm on control plane
apt-mark unhold kubeadm && \
apt-get update && \
apt-get install -y kubeadm=1.30.0-1.1 && \
apt-mark hold kubeadm

# Step 2: Verify upgrade plan
kubeadm upgrade plan                            # shows available versions

# Step 3: Apply upgrade
kubeadm upgrade apply v1.30.0

# Step 4: Drain control plane node
kubectl drain <control-plane-node> --ignore-daemonsets

# Step 5: Upgrade kubelet and kubectl on control plane
apt-mark unhold kubelet kubectl && \
apt-get install -y kubelet=1.30.0-1.1 kubectl=1.30.0-1.1 && \
apt-mark hold kubelet kubectl

# Step 6: Restart kubelet
systemctl daemon-reload
systemctl restart kubelet

# Step 7: Uncordon control plane
kubectl uncordon <control-plane-node>

# Step 8: Upgrade each worker node (repeat for each)
kubectl drain <worker-node> --ignore-daemonsets --delete-emptydir-data
# SSH to worker node, then:
apt-mark unhold kubeadm && apt-get install -y kubeadm=1.30.0-1.1 && apt-mark hold kubeadm
kubeadm upgrade node                            # upgrades node configuration
apt-mark unhold kubelet kubectl && \
apt-get install -y kubelet=1.30.0-1.1 kubectl=1.30.0-1.1 && \
apt-mark hold kubelet kubectl
systemctl daemon-reload && systemctl restart kubelet
# Back on master:
kubectl uncordon <worker-node>

# Verify upgrade
kubectl get nodes                               # should show new version

# --- etcd backup and restore (CRITICAL exam topic) ---

# Backup etcd
ETCDCTL_API=3 etcdctl snapshot save /opt/etcd-backup.db \
  --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key

# Verify backup
ETCDCTL_API=3 etcdctl snapshot status /opt/etcd-backup.db \
  --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key \
  --write-out=table

# Restore etcd from backup
ETCDCTL_API=3 etcdctl snapshot restore /opt/etcd-backup.db \
  --data-dir=/var/lib/etcd-restored \
  --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key

# Update etcd manifest to use new data dir
sudo vim /etc/kubernetes/manifests/etcd.yaml
# Change: --data-dir=/var/lib/etcd
# To:     --data-dir=/var/lib/etcd-restored
# Also update hostPath volume to /var/lib/etcd-restored

# Wait for etcd to restart, then verify cluster
kubectl get nodes

# Deployment YAML with rolling update strategy:
cat << 'EOF'
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
  namespace: my-ns
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1           # max pods above desired during update
      maxUnavailable: 0     # max pods below desired during update
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: app
        image: nginx:1.25
        resources:
          requests:
            cpu: 100m
            memory: 128Mi
          limits:
            cpu: 200m
            memory: 256Mi
        livenessProbe:
          httpGet:
            path: /healthz
            port: 8080
          initialDelaySeconds: 10
          periodSeconds: 10
        readinessProbe:
          httpGet:
            path: /ready
            port: 8080
          initialDelaySeconds: 5
          periodSeconds: 5
EOF

# 2D: POD SCHEDULING — NODE SELECTORS, AFFINITY, TAINTS, TOLERATIONS

# --- nodeSelector (simple, exact match) ---
cat << 'EOF'
spec:
  nodeSelector:
    disktype: ssd
    kubernetes.io/os: linux
EOF

# Label a node for nodeSelector:
kubectl label node my-node disktype=ssd

# --- nodeAffinity (flexible rules) ---
cat << 'EOF'
spec:
  affinity:
    nodeAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:   # hard rule
        nodeSelectorTerms:
        - matchExpressions:
          - key: disktype
            operator: In                    # In, NotIn, Exists, DoesNotExist, Gt, Lt
            values: [ssd, nvme]
      preferredDuringSchedulingIgnoredDuringExecution:  # soft rule (try to)
      - weight: 100                         # 1-100
        preference:
          matchExpressions:
          - key: zone
            operator: In
            values: [eu-west-1a]
EOF

# --- podAffinity & podAntiAffinity ---
cat << 'EOF'
spec:
  affinity:
    podAffinity:                           # schedule near pods with these labels
      requiredDuringSchedulingIgnoredDuringExecution:
      - labelSelector:
          matchExpressions:
          - key: app
            operator: In
            values: [cache]
        topologyKey: kubernetes.io/hostname  # same node
    podAntiAffinity:                       # avoid scheduling near pods with these labels
      preferredDuringSchedulingIgnoredDuringExecution:
      - weight: 100
        podAffinityTerm:
          labelSelector:
            matchLabels:
              app: my-app
          topologyKey: kubernetes.io/hostname  # spread across nodes
EOF

# --- Taints & Tolerations ---
# Taint a node (repels pods without toleration)
kubectl taint node my-node key=value:NoSchedule   # don't schedule new pods
kubectl taint node my-node key=value:NoExecute    # evict existing + don't schedule
kubectl taint node my-node key=value:PreferNoSchedule  # soft: try not to schedule
kubectl taint node my-node key:NoSchedule-         # remove taint

# Add toleration to pod so it CAN schedule on tainted node
cat << 'EOF'
spec:
  tolerations:
  - key: "key"
    operator: "Equal"         # Equal or Exists
    value: "value"
    effect: "NoSchedule"      # NoSchedule, NoExecute, PreferNoSchedule
  - key: "special"
    operator: "Exists"        # tolerate any value
    effect: "NoExecute"
    tolerationSeconds: 3600   # stay for 3600s after taint, then evict
EOF

# PV access modes:
# ReadWriteOnce (RWO)   — one node read/write
# ReadOnlyMany (ROX)    — multiple nodes read only
# ReadWriteMany (RWX)   — multiple nodes read/write
# ReadWriteOncePod (RWOP) — single pod read/write (K8s 1.22+)

# Reclaim policies:
# Retain  — keep PV after PVC deleted (manual cleanup)
# Delete  — auto-delete PV and underlying storage
# Recycle — deprecated (basic scrub)

# --- PersistentVolume (cluster-scoped) ---
cat << 'EOF'
apiVersion: v1
kind: PersistentVolume
metadata:
  name: my-pv
spec:
  capacity:
    storage: 10Gi
  accessModes:
  - ReadWriteOnce
  reclaimPolicy: Retain
  storageClassName: manual          # must match PVC storageClassName
  hostPath:                         # local storage (for testing only)
    path: /mnt/data
  # For NFS:
  # nfs:
  #   server: 192.168.1.100
  #   path: /exports/data
EOF

# --- PersistentVolumeClaim (namespace-scoped) ---
cat << 'EOF'
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: my-pvc
  namespace: my-ns
spec:
  accessModes:
  - ReadWriteOnce
  resources:
    requests:
      storage: 5Gi
  storageClassName: fast-ssd        # "" = no class, manual binding
  # For dynamic provisioning: omit storageClassName or use a defined class
  # volumeName: my-pv               # bind to specific PV
EOF

# NetworkPolicy controls traffic between pods
# Default: all traffic allowed (if no NetworkPolicy exists)
# Once a NetworkPolicy selects a pod, it blocks all traffic not explicitly allowed

# Deny all ingress to namespace
cat << 'EOF'
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: deny-all-ingress
  namespace: my-ns
spec:
  podSelector: {}               # {} = select ALL pods in namespace
  policyTypes:
  - Ingress                     # affect ingress traffic
  # no ingress rules = deny all ingress
EOF

# Deny all egress from namespace
cat << 'EOF'
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: deny-all-egress
  namespace: my-ns
spec:
  podSelector: {}
  policyTypes:
  - Egress
  # no egress rules = deny all egress
EOF

# Allow specific ingress (most common pattern)
cat << 'EOF'
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-frontend-to-backend
  namespace: my-ns
spec:
  podSelector:
    matchLabels:
      app: backend              # this policy applies to backend pods
  policyTypes:
  - Ingress
  ingress:
  - from:
    - podSelector:
        matchLabels:
          app: frontend         # allow from frontend pods in SAME namespace
    - namespaceSelector:
        matchLabels:
          name: monitoring      # allow from monitoring namespace
      podSelector:              # AND specific pods in that namespace
        matchLabels:
          app: prometheus
    ports:
    - protocol: TCP
      port: 8080
EOF

# Allow egress to specific namespace
cat << 'EOF'
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-egress-to-db
  namespace: my-ns
spec:
  podSelector:
    matchLabels:
      app: backend
  policyTypes:
  - Egress
  egress:
  - to:
    - namespaceSelector:
        matchLabels:
          name: database
    ports:
    - protocol: TCP
      port: 5432
  - to:                         # also allow DNS (or pods can't resolve names!)
    ports:
    - protocol: UDP
      port: 53
    - protocol: TCP
      port: 53
EOF

# GatewayClass: defines the controller (like IngressClass)
apiVersion: gateway.networking.k8s.io/v1
kind: GatewayClass
metadata:
  name: nginx-gateway
spec:
  controllerName: gateway.nginx.org/nginx-gateway-controller
---
# Gateway: defines listener (like a load balancer)
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: my-gateway
  namespace: my-ns
spec:
  gatewayClassName: nginx-gateway
  listeners:
  - name: http
    port: 80
    protocol: HTTP
    allowedRoutes:
      namespaces:
        from: Same              # Same, All, Selector
  - name: https
    port: 443
    protocol: HTTPS
    tls:
      mode: Terminate
      certificateRefs:
      - name: my-tls-secret
---
# HTTPRoute: routing rules (like Ingress rules)
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: my-route
  namespace: my-ns
spec:
  parentRefs:
  - name: my-gateway            # attach to Gateway
    namespace: my-ns
  hostnames:
  - "myapp.example.com"
  rules:
  - matches:
    - path:
        type: PathPrefix
        value: /api
    backendRefs:
    - name: api-svc
      port: 80
      weight: 100
  - matches:
    - path:
        type: PathPrefix
        value: /
    backendRefs:
    - name: frontend-svc
      port: 80
EOF

#   - No nodes match scheduling constraints
#   - Resource quota exceeded
#   - PVC not bound

#   - Application error (check logs)

#   - Private registry without imagePullSecrets
#   - Registry unreachable

#   - Memory limit exceeded

# EXAM SCENARIO 10: Fix a broken deployment
# "Deployment 'web-app' has pods that won't start. Fix it."
kubectl get deployment web-app
kubectl describe deployment web-app             # check Events
kubectl get pods -l app=web-app                 # check pod state
kubectl describe pod <pod>                      # check Events (ImagePullBackOff, etc.)
kubectl logs <pod>                              # application error
# Common fixes:
kubectl set image deployment/web-app nginx=nginx:1.25  # fix wrong image
kubectl edit deployment web-app                         # fix env vars, resources, etc.

# "Service 'api-svc' is not accessible. Find and fix the issue."

# SCENARIO A: Multi-container pod with shared volume
# "Create a pod 'shared-pod' with two containers:
#  1. 'writer' (busybox) that writes date to /shared/data.txt every 5 seconds
#  2. 'reader' (busybox) that reads from /shared/data.txt
#  Use an emptyDir volume named 'shared-data'"
cat << 'EOF' | kubectl apply -f -
apiVersion: v1
kind: Pod
metadata:
  name: shared-pod
spec:
  volumes:
  - name: shared-data
    emptyDir: {}
  containers:
  - name: writer
    image: busybox
    command: ["/bin/sh", "-c", "while true; do date >> /shared/data.txt; sleep 5; done"]
    volumeMounts:
    - name: shared-data
      mountPath: /shared
  - name: reader
    image: busybox
    command: ["/bin/sh", "-c", "tail -f /shared/data.txt"]
    volumeMounts:
    - name: shared-data
      mountPath: /shared
EOF

# SCENARIO B: Init container
# "Create a pod 'init-pod' with an init container 'setup' (busybox)
#  that creates /data/ready.txt, and a main container 'app' (nginx)
#  that starts after init completes. Mount /data as emptyDir."
cat << 'EOF' | kubectl apply -f -
apiVersion: v1
kind: Pod
metadata:
  name: init-pod
spec:
  volumes:
  - name: data
    emptyDir: {}
  initContainers:
  - name: setup
    image: busybox
    command: ["sh", "-c", "echo initialized > /data/ready.txt"]
    volumeMounts:
    - name: data
      mountPath: /data
  containers:
  - name: app
    image: nginx
    volumeMounts:
    - name: data
      mountPath: /data
EOF

# --- Create kubeconfig for a user ---
# Step 1: Create private key
openssl genrsa -out alice.key 2048

# Step 2: Create CSR
openssl req -new -key alice.key -out alice.csr \
  -subj "/CN=alice/O=dev-team"            # CN=username, O=group

# Step 3: Create Kubernetes CertificateSigningRequest
cat << 'EOF' | kubectl apply -f -
apiVersion: certificates.k8s.io/v1
kind: CertificateSigningRequest
metadata:
  name: alice-csr
spec:
  request: $(cat alice.csr | base64 | tr -d '\n')
  signerName: kubernetes.io/kube-apiserver-client
  usages:
  - client auth
EOF

# Step 4: Approve CSR
kubectl certificate approve alice-csr
kubectl get csr alice-csr                   # should be Approved,Issued

# Step 5: Get certificate
kubectl get csr alice-csr -o jsonpath='{.status.certificate}' | base64 -d > alice.crt

# Step 6: Create kubeconfig
kubectl config set-cluster my-cluster \
  --certificate-authority=/etc/kubernetes/pki/ca.crt \
  --server=https://<api-server>:6443 \
  --kubeconfig=alice.kubeconfig

kubectl config set-credentials alice \
  --client-certificate=alice.crt \
  --client-key=alice.key \
  --kubeconfig=alice.kubeconfig

kubectl config set-context alice@my-cluster \
  --cluster=my-cluster \
  --user=alice \
  --namespace=my-ns \
  --kubeconfig=alice.kubeconfig

kubectl config use-context alice@my-cluster --kubeconfig=alice.kubeconfig

# --- Check certificate expiry ---
# Control plane certificates (typically 1 year):
kubeadm certs check-expiration
# Or manually:
openssl x509 -in /etc/kubernetes/pki/apiserver.crt -noout -dates

# Renew certificates
kubeadm certs renew all                     # renew all control plane certs
kubeadm certs renew apiserver               # renew specific cert

# StatefulSet: ordered, sticky identity for pods
# Use for: databases, distributed systems needing stable network identity

cat << 'EOF'
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: my-db
spec:
  serviceName: "my-db"                      # headless service name (required)
  replicas: 3
  selector:
    matchLabels:
      app: my-db
  template:
    metadata:
      labels:
        app: my-db
    spec:
      containers:
      - name: db
        image: postgres:15
        ports:
        - containerPort: 5432
        volumeMounts:
        - name: data
          mountPath: /var/lib/postgresql/data
  volumeClaimTemplates:                     # creates PVC per pod
  - metadata:
      name: data
    spec:
      accessModes: ["ReadWriteOnce"]
      resources:
        requests:
          storage: 10Gi
---
# Required headless service for StatefulSet DNS
apiVersion: v1
kind: Service
metadata:
  name: my-db
spec:
  clusterIP: None                           # headless
  selector:
    app: my-db
  ports:
  - port: 5432
EOF

# StatefulSet pod naming: <name>-0, <name>-1, <name>-2
# DNS: <pod>.<service>.<namespace>.svc.cluster.local
# Example: my-db-0.my-db.default.svc.cluster.local

### Domains covered (overview)

#### Cluster Architecture, Installation & Configuration (25%)

- **RBAC**: Roles, ClusterRoles, RoleBindings/ClusterRoleBindings, `kubectl auth can-i`.
- **kubeadm**: `init`, `join`, full **upgrade workflow**, token management.
- **etcd**: snapshot backup and restore with correct certs and data dirs.
- **Helm & Kustomize**: install/upgrade/rollback, templating, repo management, `kustomization.yaml`.
- **CRDs & Operators**: inspect CRDs, interact with custom resources, install operators via Helm.
- **Extension interfaces**: CNI, CSI, CRI — what they are and how to inspect them.
- **Certificates & kubeconfig**: CSR, approve, create user kubeconfig, renew control‑plane certs.
- **Static pods & HA concepts**.

#### Workloads & Scheduling (15%)

- **Deployments**: rolling updates, rollback, pause/resume, history, scaling.
- **ConfigMaps & Secrets**: create, consume via env/envFrom/volumes.
- **Autoscaling**: HPA (and awareness of VPA).
- **Scheduling controls**: `nodeSelector`, node/pod affinity and anti‑affinity, taints/tolerations.
- **Resources & quotas**: requests/limits, `LimitRange`, `ResourceQuota`, `PriorityClass`.
- **Workload types**: Pods, Deployments, DaemonSets, Jobs, CronJobs, Init containers, multi‑container pods, StatefulSets, static pods.

#### Storage (10%)

- **StorageClasses** and dynamic provisioning.
- **PVs/PVCs**: access modes, reclaim policies, binding and phases.
- **Volume types**: `emptyDir`, `hostPath`, `configMap`, `secret`, PVC, memory‑backed volumes.

#### Services & Networking (20%)

- **Service types**: ClusterIP, NodePort, LoadBalancer, ExternalName, headless.
- **Endpoints** and endpoint debugging.
- **NetworkPolicies**: ingress/egress, deny‑all and allow‑specific patterns, DNS egress.
- **Ingress**: rules, TLS, `pathType`, `ingressClassName`.
- **Gateway API**: `GatewayClass`, `Gateway`, `HTTPRoute` basics.
- **CoreDNS**: config, DNS naming, troubleshooting and testing from pods.

#### Troubleshooting (30%)

- **Cluster components**: nodes, control plane pods, kubelet, CNI, kube‑proxy.
- **Pod lifecycle issues**: Pending, CrashLoopBackOff, ImagePullBackOff, OOMKilled, stuck terminating.
- **Service & networking**: selectors, endpoints, DNS, Ingress, NetworkPolicy.
- **Observability**: `kubectl top`, logs, events, `kubectl debug`, ephemeral containers.
- **Node‑level debugging**: `systemctl`, `journalctl`, resource pressure analysis.

#### Exam technique & workflow

- **Context handling**: switch context/namespace for every task.
- **Aliases & completion**: speed up `kubectl` usage.
- **Dry‑run + edit**: generate YAML, edit, then `kubectl apply -f`.
- **`kubectl explain`**: use instead of web searching for field details.
- **Time management**: prioritize high‑value tasks, skip and return, accept partial credit.
